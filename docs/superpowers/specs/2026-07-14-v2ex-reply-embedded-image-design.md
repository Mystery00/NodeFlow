# V2EX 回复大图分类修复设计

## 背景

V2EX 主题 `1227054` 的第 10 楼（回复 ID `17861724`）包含一张
`955×588` 的 Imgur 图片。网页将其渲染为：

```html
回复文字
<a href="https://i.imgur.com/HhIXhII.png">
  <img class="embedded_image" src="https://i.imgur.com/HhIXhII.png">
</a>
```

图片资源本身返回 HTTP 200，不要求 Cookie、Referer 或特殊 User-Agent。
NodeFlow 的 `HtmlText` 会因为图片链接前存在同级文字，将图片判定为内联小图，
从而限制为最多 `56dp` 并禁止点击预览。这使正常正文大图看起来像没有显示。

## 目标

- V2EX 明确标记为 `embedded_image` 的回复图片按正文大图展示。
- 图片即使紧邻回复文字，也能使用可用宽度并支持点击预览。
- 保留 emoji、表情、小尺寸图片以及缺少明确语义的普通内联图现有行为。

## 非目标

- 不修改图片网络请求、缓存、重试或预览器实现。
- 不改变主题正文 WebView 的图片逻辑。
- 不扩大支持新的图片 URL 后缀或第三方图床。

## 方案比较

### 方案一：删除内联图片启发式

所有未知尺寸图片都按正文大图显示。实现简单，但可能把真正的行内装饰图放大，
影响范围过大。

### 方案二：等待图片加载后再分类

根据图片真实尺寸决定布局。判断更精确，但首次加载仍会使用错误占位尺寸，容易产生
明显重排，而且需要调整 Coil 状态与布局状态机。

### 方案三：显式正文图片语义优先（采用）

保留现有启发式，但当图片具有 V2EX 的 `embedded_image` 类时，不再仅因相邻文字而
判定为内联小图。图片自身的 emoji 类、明确小尺寸或短符号 `alt` 仍可将其判定为小图。

该方案直接使用服务端提供的语义，修改范围最小，并且不会改变未知 HTML 的默认行为。

## 实现设计

在 `HtmlText` 的图片规格提取阶段增加“显式正文图片”判断：

1. 继续读取图片的宽高、类名、`alt` 与相邻节点。
2. 先保留既有的小尺寸、emoji 类及短符号 `alt` 判断。
3. 只有图片不是 `embedded_image` 时，才允许“相邻存在文字”将其判定为内联小图。
4. 规格为非紧凑图片时，沿用现有全宽布局和点击预览逻辑。

数据流保持不变：

`回复 HTML → extractHtmlImageSpecs → HtmlImageSpec.compact=false → HtmlImage 全宽布局 → 点击打开 ZoomableImageViewer`
