# UI、导航与状态管理

## UDF/MVI

Feature 层通常由 `XxxScreen.kt`、`XxxViewModel.kt`、`XxxUiState.kt` 和 `XxxUiEvent.kt` 组成。

- Screen 渲染不可变 UiState，并将用户意图转换为 UiEvent。
- ViewModel 使用 StateFlow 暴露状态并调用 UseCase。
- 加载、刷新、分页、空数据、成功、失败和受限访问应可明确区分。
- 一次性导航或提示沿用现有事件模式，不作为永久状态反复消费。
- 可测试的状态与布局计算不应隐藏在大型 Composable 中。
- 已有内容时刷新保留内容，刷新期间禁用刷新按钮。“我的”、用户资料及列表页使用官方 Material 3 Expressive `PullToRefreshDefaults.LoadingIndicator`，横向刷新和分页进度使用 `LinearWavyProgressIndicator`；不再以自绘圆点或波浪模拟官方效果。相关 Material 3 预发布版本在版本目录中独立固定。
- 已有内容时，“我的”、用户资料、首页、节点列表、节点详情和消息页的刷新失败通过带重试操作的 Snackbar 显示；收藏列表保留原有行内错误及重试。个人资料或概览部分请求失败也应提示并保留对应旧数据。主题详情的刷新进度和错误提示位于顶部栏下方，不被遮挡。

## Compose 与 Material 3

- 新增 UI 只使用 Compose，不新增 XML layout。
- 使用 `MaterialTheme`、Dynamic Color、深色模式和 edge-to-edge。
- 正确处理 WindowInsets 与 Scaffold padding，避免重复消费。
- 长列表使用惰性组件和稳定 key；状态收集应感知生命周期。
- 文案优先放入 string resource，并考虑字体缩放、无障碍语义和点击区域。

## 登录与两步验证

- 登录页沿用 Material 3，表单最大宽度为 480dp；内容可滚动并处理 IME 避让，紧凑屏幕和大字体下仍可到达提交按钮。
- 用户名/邮箱、密码和图片验证码依次支持键盘“下一项/完成”。密码保留原始字符并声明密码自动填充语义；用户名和图片验证码沿用 ASCII 输入规则。
- 图片验证码提供加载、显示、失败和重新加载状态；换图只清理旧验证码与挑战，保留账号及密码。图片不可解码时 UI 不允许提交。
- 服务端要求两步验证后，顶部栏切换为“两步验证”，展示账号与“账号密码已验证”说明；不再呈现密码或图片验证码，也没有重新获取登录验证码的入口。该阶段释放第一步密码和挑战，只保留第二步所需状态。
- 两步验证使用一个可粘贴的数字输入框，输入归一为最多六位 ASCII 数字，完整六位才可提交，不自动发送。失败保留当前阶段，修改输入清除旧错误；实际请求协议仍见[网络与认证](network-auth.md)。
- 提交期间禁用输入、显隐密码、换图和重复提交；ViewModel 同步进入忙碌状态，防止快速连续事件重复发起请求。错误提示使用具备 live region 语义的区域，不单靠颜色表达；按钮进度采用固定尺寸，不改变按钮高度。
- `AuthScreenTest` 验证键盘、紧凑布局、提交锁定及验证码重试；`AuthDesignCaptureTest` 仅在显式传入 `authDesignCapture=before/after` 时用虚构状态生成截图，不访问认证网络。它们均运行在独立 `deviceTest` 包，不操作日常安装。

## 导航

根 NavHost 管理全屏详情页面，MainShell 管理带底部导航的一级页面。路由集中定义在 `navigation` 包，不在 Screen 中散落字符串。

- 外部深链和应用内链接共用 V2EX 链接解析规则。
- 参数必须可恢复，并按需编码/解码。
- 链接解析与跳转应有浏览器或错误提示回退；具体实现见 `V2exLinkParser` 和 `NodeFlowNavHost`，不要把所有导航异常都视为已自动处理。
- Manifest 声明 V2EX 主题、节点和用户的 HTTP(S) 深链，但没有域名验证；Android 12+ 是否自动交给应用取决于系统默认打开设置，不能承诺安装后自动接管所有 V2EX 链接。
- 修改层级、转场或 padding 时运行导航和布局相关测试。
- 帖子列表和帖子详情中的节点 Chip 复用统一的节点标题/名称映射，并通过根导航进入节点详情页。
- 帖子列表对显式置顶标记（`corner_star.png` 背景、class、data 属性或标签）展示“置顶”状态 Chip，不再依据时间顺序异常推断；它与节点 Chip 视觉一致，但不可点击且不提供按钮语义。
- 帖子详情中发帖人和每条回复作者的头像、用户名都通过根导航进入对应用户详情页；空用户名不产生导航。
- 节点详情页提供账号级节点屏蔽入口：未登录时进入现有登录页，已登录时必须二次确认；请求期间禁止重复提交，成功后由结果对话框返回上一页。
- 首页、节点分类和已登录的消息列表共用 `enterAlways` 顶部栏滚动行为：向上滑动列表时收起标题栏，反向滑动时立即展开，无需回到列表顶部；未登录的消息页保持固定标题栏。
- 已位于首页时重复点击首页底部导航项，应展开顶部 App Bar、滚动主题列表到顶部并刷新；从其他一级页面点击首页只执行导航。
- 主页面底部导航固定为“首页、节点、消息、我的”。消息入口通过 Badge 展示共享未读数：超过 99 条显示 `99+`，加载完成后无法获取未读数时显示 `!`，加载中、未读数为 0 或未登录时不显示。查看帖子时从已有 HTML 响应顺带更新数量，不额外请求消息；点击“消息”不立即清零，只有通知页成功解析后才更新已读状态。消息页由 `MainShell` 内部 NavHost 管理；未登录时展示登录引导且不创建通知分页请求，通知中的用户和主题详情仍由根 NavHost 打开。
- “我的”登录后在个人信息下方依次提供“收藏主题”和“设置”列表入口，退出登录按钮保留在最后；右上角仅保留刷新，未登录或个人信息加载失败时也保留页面内的设置入口。点击“收藏主题”通过根 NavHost 打开独立收藏列表，不显示底部导航。列表复用 `TopicListItem`，点击主题进入现有详情；支持刷新、分页、空态和失败重试，从详情返回时重新获取收藏状态。首屏请求或翻页发现登录失效时提供登录入口，账号切换或退出登录时清空收藏列表内存。
- 通知主题链接可携带目标回复楼层；主题详情按需顺序补页到目标楼层后滚动到对应回复并短暂高亮，楼层不存在时安全停留在主题顶部。
- “我的”页面使用紧凑横向头像和用户名，会员编号、加入日期与排名降为次要信息，简介最多三行；财富与签到置于独立浅色圆角卡片，金额和签到操作在窄屏、大字体下自动换行。“收藏主题”和“设置”共用连续列表分组，退出登录作为最后一个低强调按钮，确认后才触发退出。未登录和资料加载失败时仍可访问设置。
- “我的”页面财富/签到卡片顶部显示全局共享的“今日活跃度：百分比”，其下一条确定型横向细进度条位于文案与账户财富之间，左右与卡片内容边距对齐，兼作分隔。活跃度为空时省略该区域；只有活跃度而无财富/签到时仍可显示卡片。进度颜色跟随主题，向无障碍服务提供确定型进度语义；列表和详情更新共享值时无需重新加载账户资料，手动刷新复用原有概览请求。
- 主题详情回复按页加载：进入只抓第 1 页，滚动接近尾部自动加载下一页；刷新重拉已加载页并保持位置；收到回复提交成功结果后补页到最后一页，尝试定位返回的楼层。该楼层当前由提交前末楼层加一推算，并非服务端确认值；提交成功判定见[网络与认证](network-auth.md)。分页状态由 `TopicDetailPager` 承载。
- 回复编辑器不展示图床选择，上传使用设置中的“回复图片上传图床”；上传期间锁定正文、发布和清空操作。匿名选择图片不会预先要求 V2EX 登录，只有具体的 `AuthenticationRequired` 结果才请求登录。适配器自动上传成功时将直链插入正文；只有结果带 `OpenHostPage` 时才展示网页恢复入口，外部浏览器的手动上传没有自动回填或会话回传。
- 上传恢复动作只保留当前请求的结构化状态，成功或切换 provider 后清理；请求绑定 host、主题和编辑版本，但未绑定账号世代，不能据此承诺账号切换后的旧结果隔离。
- 回复草稿按主题恢复，正文修改后防抖 400 毫秒保存，关闭编辑器或页面收到 `ON_STOP` 时发起补写；这些异步保存不等于强杀进程前必定落盘。账号变化只更新登录状态，未清空编辑内容；草稿没有账号归属。提交收到成功结果时关闭编辑器、清空内容并尝试删除草稿，详情见[存储说明](storage.md)。
- 主题详情在登录页面解析到感谢入口时提供主题感谢；回复更多菜单在该回复可感谢时提供“感谢回复者”。两类操作都必须二次确认，回复感谢明确提示消耗 10 个铜币；请求期间禁止重复提交，成功后更新当前页面状态和共享 `once`，不为刷新网页余额额外请求 `/ajax/money`。

## 排障入口

UI 状态异常时检查 UiEvent 到 ViewModel 的处理、UseCase 返回、StateFlow 更新和生命周期收集；导航异常时检查目的地、根/内部 NavController、参数编码、返回栈与 `V2exLinkParser`。
