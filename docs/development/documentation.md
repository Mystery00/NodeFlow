# 文档规范

## 文档目标

根目录 `AGENTS.md` 是 Agent 的首要入口和任务路由，`README.md` 是面向访客的项目主页，`docs/` 保存所有详细设计、规范和调查资料。不要在三处重复维护同一段详细内容。

## 目录分类

```text
docs/
├── index.md            # 完整索引
├── architecture/       # 总体架构、模块边界和长期技术决策
├── development/        # 开发、测试、文档和交付规范
├── subsystems/         # 可独立理解的业务或技术子系统
├── plans/              # 带日期的设计说明和实施计划
└── investigations/     # 问题调查、抓包结论和外部行为研究
```

## 新文档落位

- 长期有效的全局架构说明放入 `architecture/`。
- 长期有效的开发协作规则放入 `development/`。
- 某个稳定子系统的结构、约束和排障入口放入 `subsystems/`。
- 新需求设计和实施计划统一放入 `plans/`，不再创建 `docs/superpowers`、`specs` 或其他计划目录。
- 调查结果放入 `investigations/`；调查转为正式规则后，应同步更新对应专题文档。
- 图片和附件放入所属文档目录下的 `assets/`，使用相对链接。

## 命名规范

- 专题文档使用稳定的小写英文短横线名称，例如 `network-auth.md`。
- 设计文档使用 `YYYY-MM-DD-主题-design.md`。
- 实施计划使用 `YYYY-MM-DD-主题.md`；同一主题与设计文档共享日期和主题名。
- 调查文档使用 `YYYY-MM-DD-主题.md`。

## 维护要求

- 新增、移动或删除文档后，必须更新 `docs/index.md`；若影响任务查找，还要更新 `AGENTS.md` 的文档路由。
- 文档使用中文，代码符号、路径和专业术语保留原文。
- 历史计划原则上保留，不把已经发生的决策改写成当前事实；过时内容在专题文档中给出现行结论。
- 文档引用使用相对路径，并在完成前检查失效链接和旧 `docs/superpowers` 路径。
- README 只保留图标、简要说明、下载、编译、贡献和许可证等项目概要，不承载详细架构与子系统说明。
