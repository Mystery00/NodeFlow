# V2EX 受限内容访问与正文解析修复设计

## 背景

主题 `1221181` 已被移动到受限节点“水深火热”。当前应用在已登录且具备访问权限时能够取得主题页面，但正文错误显示节点统一的管理员说明；未登录或账号权限不足时，V2EX 会把主题请求重定向到受限页或登录页，应用却可能把它当作普通主题或回退旧 JSON API，最终显示空正文和公开回复，未向用户说明权限问题。

本次实机复现确认：

- 已登录且有权限时，`GET /t/1221181` 返回 HTTP 200，标题、作者和 25 条回复均正常，但解析器取到了真实正文之外的第一个 `.topic_content`。
- 未登录时，请求链为 `/t/1221181` → `/restricted` → `/signin?next=%2Frestricted`。
- 旧 JSON API 仍返回主题元数据和回复，但该主题的 `content` 与 `content_rendered` 为空。
- 未登录访问 `/go/flamewar` 会被重定向到首页；当前节点解析链可能把首页主题误标为 `flamewar` 节点主题。

## 目标

1. 已登录且具备权限时，显示 `#Main` 中的真实主题正文，不显示节点管理员说明。
2. 未登录或当前账号权限不足时，在主题详情页显示明确的全页访问提示。
3. 从列表、其他主题中的链接或外部浏览器深链进入主题详情时，行为保持一致。
4. 未登录或无权限访问受限节点时，节点页显示访问提示，不解析重定向目标中的无关主题。
5. 权限错误不得被 JSON API、详情缓存或刷新时保留的旧页面状态掩盖。
6. 普通公开主题、公开节点和非权限类网络失败维持现有行为。

## 非目标

- 不自动发起登录，也不新增登录按钮或账号切换流程。
- 不尝试推断 V2EX 的账号等级规则。
- 不硬编码主题 ID `1221181`、节点名 `flamewar` 或管理员提示文案。
- 不改变回复解析、富文本渲染、分页规则或数据库结构。
- 不在本次工作中实现完整离线权限模型；网络不可达且服务器无法返回权限结论时，沿用现有缓存降级语义。

## 方案选择

采用“最终响应 URL 为主、HTML 结构为辅”的集中权限判定。

仅依赖页面文案容易受模板和语言变化影响；仅根据正文是否为空会误判合法空正文，也无法识别节点被重定向到首页。OkHttp 跟随重定向后保留在 Retrofit `Response.raw().request.url` 中的最终 URL，是当前请求是否仍停留在预期资源上的更稳定信号。HTML 登录表单结构用于防御测试夹具或服务端返回登录页但最终 URL 信息不可用的情况。

## 详细设计

### 1. 权限错误类型

在 `NodeFlowException.Kind` 中新增 `AccessDenied`，与 `Auth` 区分：

- `Auth` 表示登录流程或已有会话失效等身份认证问题。
- `AccessDenied` 表示本次内容请求已被 V2EX 拒绝，既可能是未登录，也可能是已登录账号权限不足。

主题与节点可以分别提供具体消息，但默认用户提示统一为：

> 当前账号无权访问此内容；如果尚未登录，请登录具有访问权限的账号后重试。

### 2. 响应访问判定

新增可被主题与节点数据源复用的响应判定逻辑，读取最终响应 URL，不读取或记录 Cookie、Authorization 等敏感字段。

主题请求判定为拒绝访问的条件：

- 最终路径为 `/restricted`；或
- 最终路径为 `/signin`；或
- HTML 包含 `form[action=/signin]` 以及密码输入框，或登录表单的隐藏 `next` 字段指向 `/restricted`。

节点主题列表请求判定为拒绝访问的条件：

- 最终路径为 `/restricted` 或 `/signin`；或
- 请求 `/go/{name}` 后最终路径变为 `/`；或
- HTML 包含上述实际登录表单结构。

普通页面顶部存在“登录”链接不能单独作为拒绝访问依据，因为未登录用户也能正常阅读公开主题。DOM 兜底只使用表单级特征，不根据可见提示文案判断。

如新增诊断日志，日志内容必须使用英文，并且不得包含 Cookie、令牌或完整响应正文。

### 3. 主题 HTML 解析

`V2exHtmlParser.parseTopicHtml` 按以下优先级定位正文：

1. `#Main .topic_content`
2. 仅为兼容现有片段测试和缺少 `#Main` 的合法模板，才回退到全局 `.topic_content`

在正文选择前先排除包含真实登录表单的页面。这样既能避免把 `#problem.topic_content` 当成主题，也能在“节点管理员说明”和真实正文同时存在时选中 `#Main` 下的正文。

主题页面仍需至少具备正文或回复行之一；不满足时返回 `null`，交由数据源判断是否允许 JSON 兜底。

### 4. 主题数据源与 JSON 兜底

`TopicRemoteDataSource` 在解析正文前完成权限判定：

1. 请求 HTML 并保留 Retrofit 响应对象。
2. 检查最终 URL 和 HTML 页面级特征。
3. 若拒绝访问，抛出 `AccessDenied`。
4. 若为正常主题，解析 HTML 并继续现有多页回复合并流程。
5. 只有普通 HTML 请求失败、结构无法解析或正文确实不可用时，才允许回退 JSON API。

现有 `runCatching { htmlTopicDetail(...) }.getOrNull()` 必须改为让 `AccessDenied` 穿透；否则权限异常仍会被吞掉并重新进入 JSON 兜底。

### 5. 仓库缓存边界

主题详情缓存没有记录账号或访问权限，因此不能在未校验服务器的情况下证明当前会话仍然有权访问。

调整规则：

- 打开主题详情时先尝试远端请求，不再因存在本地详情而直接短路返回。
- 服务器明确返回 `AccessDenied` 时，禁止使用本地缓存替代。
- 普通网络、HTTP 或解析错误仍可按现有完整性条件回退缓存。
- 权限失败结果不写入详情缓存。

这会让无回复主题多一次远端权限校验，但能避免注销或更换账号后直接显示先前缓存的受限正文。

### 6. 主题详情状态与界面

沿用 `TopicDetailScreen` 已有的全页 `ErrorContent`，不新增平行页面组件。

`TopicDetailViewModel` 的失败处理区分两类：

- `AccessDenied`：清空当前 `detail`，停止加载与刷新，并设置权限提示，使界面进入全页错误状态。
- 其他刷新错误：保留当前详情并显示现有顶部错误条，维持弱网体验。

清空详情可以避免用户先有权限加载正文、随后退出登录或切换为无权限账号并刷新时，旧正文仍显示在错误条下方。

### 7. 受限节点页

`NodeRemoteDataSource.topics` 在调用 `parseTopicList` 前检查最终响应 URL。若 `/go/{name}` 被重定向到首页、登录页或受限页，抛出 `AccessDenied`，不得解析重定向目标中的主题。

节点页现有 Paging `LoadState.Error` 和 `ErrorContent` 可直接显示权限消息；公开节点仍按原流程分页。节点基础信息继续允许使用公开 API 或缓存，因为主题列表的权限错误会控制页面主体，不会展示错误列表数据。

## 数据流

### 有权限主题

`入口 → TopicDetailViewModel → Repository → HTML 响应仍为 /t/{id} → #Main 正文解析 → 缓存 → 详情页`

### 无权限主题

`入口 → TopicDetailViewModel → Repository → 最终 URL/DOM 判定拒绝 → AccessDenied → 禁止 JSON/缓存兜底 → 清空详情 → 全页提示`

### 无权限节点

`节点入口 → PagingSource → /go/{name} 跳转首页或受限页 → AccessDenied → 禁止解析首页主题 → 全页提示`

## 测试设计

所有实现遵循测试先行，至少覆盖：

1. 页面同时含节点管理员说明和 `#Main` 正文时，只返回真实正文。
2. 含 `#problem.topic_content` 和登录表单的真实登录页不能解析为主题。
3. 主题最终 URL 为 `/restricted` 时返回 `AccessDenied`，且 JSON 主题与回复 API 调用次数均为零。
4. 主题最终 URL 为 `/signin?next=/restricted` 时行为相同。
5. 普通未知 HTML 仍允许 JSON 兜底，保持现有兼容能力。
6. 远端返回 `AccessDenied` 时，仓库不得返回旧缓存。
7. 无本地详情时显示全页权限提示。
8. 已显示详情后刷新得到 `AccessDenied` 时清空旧详情；普通网络刷新失败仍保留详情。
9. 节点 `/go/{name}` 最终跳到 `/` 时返回 `AccessDenied`，不得把首页主题标记为该节点。
10. 公开主题正文、公开节点分页和现有相关测试全部通过。

实机验证使用当前已登录且有权限的模拟器账号，确认主题 `1221181` 显示真实正文而非管理员说明。未登录和低权限分支通过匿名浏览器实证、重定向夹具及 JVM 测试验证，不退出或清除模拟器中的现有账号。

## 验收标准

- 登录且有权限访问 `1221181` 时，正文不再包含“这个节点的存在，只是为了将一类信息进行归类”等节点说明。
- 匿名或低权限响应落到 `/restricted`、`/signin` 时，详情页显示统一权限提示，不显示空正文、公开回复或旧缓存正文。
- 受限节点跳转首页时，节点页显示权限提示，不显示被错误归类的首页主题。
- 其他公开主题和节点行为无回归。
- 相关单元测试和 `testDebugUnitTest` 通过；当前模拟器上的授权访问场景验证通过。
