# 通知中心设计

## 目标

将个人页现有的只读“未读提醒”数字升级为可进入的通知中心，分页展示 V2EX 的全部历史通知。消息卡片展示发送者、动作、帖子标题、时间、回复正文；通知正文明确包含 `@用户名 #楼层` 时，再展示对应原回复的引用卡片。

## 入口与导航

- 移除个人资料信息区中的“未读提醒”行。
- 在个人页 Top App Bar 增加铃铛按钮，使用 Material 3 `BadgedBox` 显示未读数；0 条时不显示数字 Badge。
- 点击铃铛进入现有根级 `notification` 目的地，并在本地清除已展示的 Badge；服务器通知页加载失败时不伪造通知数据。
- 通知页提供返回按钮。点击消息的帖子标题或卡片进入帖子详情，并携带回复楼层；详情加载完成后滚动并高亮对应回复。

## 数据来源与页面分类

- 使用现有 Retrofit/OkHttp/Cookie 会话请求 `GET /notifications?p=N`。
- RemoteDataSource 必须校验最终 URL 为 HTTPS、`www.v2ex.com` 和 `/notifications`，并排除登录页、受限页、Cloudflare 与异常 HTML。
- HTML Parser 以 `#Main .cell[id^=n_]` 为通知项，以 `.fade`、`.snow`、`.payload`、`a.topic-link[href^=/t/]` 和头像/用户链接提取数据。
- 每页最多 50 条；PagingSource 从第 1 页开始，空页或不足 50 条时停止继续加载。

## 模型与引用解析

`Notification` 保存：通知 ID、发送者、动作说明、帖子 ID/标题、目标回复楼层、服务端相对时间、富文本正文和可选引用定位。

通知页本身不包含原回复正文。只有正文明确出现 `@用户名 #楼层` 时才创建引用定位；Repository 按涉及的帖子去重加载 TopicDetail，从对应楼层取得作者和摘要，构造引用预览。加载失败、楼层不存在或用户名不匹配时省略引用卡片，不推断数据，也不影响通知列表主体。

## UI

- 使用 `LazyColumn` + Paging 3，支持首次加载、空状态、刷新、追加加载失败与重试。
- 卡片视觉层级参考帖子回复但不复刻：头像和发送者位于顶部，动作与时间使用次级颜色，帖子标题单独可点击，引用使用浅色描边 Surface，正文复用 `HtmlText`，链接和图片沿用现有路由与预览能力。
- 感谢等没有 `.payload` 的通知仍展示发送者、动作、帖子和时间；没有正文时不显示空白正文区。

## 错误与隐私

- 登录失效返回 Auth 错误；访问限制返回 AccessDenied；DOM 或最终 URL 异常返回 Parse。
- 不记录通知正文、用户名、Cookie 或完整响应 HTML。
- 网络测试只使用脱敏 fixture 和测试替身，不访问真实 V2EX。

## 验证

- Parser：回复、感谢、富文本、分页、缺失字段、登录/受限页面。
- PagingSource：首页、追加、末页、错误、引用解析失败降级。
- ViewModel/导航：刷新、Badge 消费、带楼层路由。
- Compose：模拟器验证深浅色、长标题、长正文、空状态、分页错误和返回行为。
