# 导航转场体验调整设计

## 背景

当前路由层级已经区分了一级页面和详情页面，但底部导航栏仍由同一个根 `Scaffold` 根据当前 route 立即显示或隐藏。点击帖子或节点进入详情时，详情数据还在加载，底部导航栏会先瞬间消失；返回时底部导航栏又瞬间出现，视觉上像页面在跳变。

这个问题的根因不是数据加载，而是底部导航栏和详情页处在同一个路由容器里，底栏显示状态直接绑定当前 route。

## 目标

调整导航结构，让底部导航栏属于一级页面容器，而不是根导航容器：

- 首页、节点列表、设置页作为主页面区域，稳定显示底部导航栏。
- 帖子详情页、节点详情页作为根级全屏页面覆盖主页面。
- 进入详情时，主页面和底部导航栏一起被新页面覆盖，不再单独突然消失。
- 返回详情时，详情页退场，下面的主页面和底部导航栏自然恢复。
- 不改变现有业务数据加载逻辑。

## 推荐架构

使用根 `NavHost` + 主页面 Shell 的结构：

- 根 `NavHost`
  - `main`：主页面 Shell。
  - `topic/{topicId}`：帖子详情页。
  - `node/{nodeName}`：节点详情页。
  - 其他预留详情或全屏页面。

主页面 Shell 内部包含：

- `Scaffold`
- `NavigationBar`
- 内部 `NavHost`
  - `home`
  - `nodes`
  - `settings`

这样底部导航栏只跟随主页面 Shell 存在。根级详情页出现时，它覆盖整个主页面 Shell；底栏不是被隐藏，而是被详情页盖住。

## 转场策略

根级详情页使用简洁的 Android 风格转场：

- 进入详情：从右向左滑入，并轻微淡入。
- 返回详情：向右滑出，并轻微淡出。
- 主页面 Shell 保持在下层，不参与底栏单独动画。

一级页面之间暂时不做复杂转场，保持底部导航切换的即时性。

## 跳转规则

- 首页点击帖子：根导航进入 `topic/{topicId}`。
- 首页点击节点 chip：根导航进入 `node/{nodeName}`。
- 节点列表点击节点 chip：根导航进入 `node/{nodeName}`。
- 帖子详情点击节点 chip：根导航进入 `node/{nodeName}`。
- 节点详情点击帖子：根导航进入 `topic/{topicId}`。
- 详情页返回：根导航 `popBackStack()`。

## 文件边界

计划新增或调整：

- `NodeFlowNavHost.kt`：只负责根级导航和详情页转场。
- `MainShell.kt`：承载底部导航栏和一级页面内部导航。
- `NodeFlowDestinations.kt`：新增 `Main` 路由，保留现有一级和详情路由。
- 导航相关单元测试：覆盖根级详情路由、主页面路由和底部导航目标。

## 验收标准

- 首页、节点列表、设置页显示底部导航栏。
- 进入帖子详情和节点详情时，底部导航栏不再先于页面转场突然消失。
- 详情页显示左上角返回按钮。
- 返回详情页时，主页面和底部导航栏自然恢复。
- 构建、lint、单元测试通过。
- 模拟器截图验证主页面、详情页和返回行为。
